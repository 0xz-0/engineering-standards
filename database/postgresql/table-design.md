# PostgreSQL 表设计规范

> **约束力**：MUST
> **适用范围**：PostgreSQL 业务库
> **说明**：通用表设计原则见[数据库表设计规范](../table-design.md)，本文仅约定 PostgreSQL 的落地差异。

## 1. 字段类型选型

| 语义 | 强制类型 | 说明 |
| :--- | :--- | :--- |
| 主键 `id` | `bigint` + `GENERATED BY DEFAULT AS IDENTITY` | **严禁 `GENERATED ALWAYS`**（禁止显式插入 id，数据迁移/订正时需 `OVERRIDING SYSTEM VALUE`，极易踩坑）；**严禁 `BIGSERIAL`**（非标准 SQL，与 IDENTITY 混用会导致风格分裂） |
| 业务编号（`no`/`code`）、枚举、名称等字符串 | `TEXT` | **严禁 `VARCHAR(N)` / `CHAR(N)`**。PG 中 `TEXT` 与 `VARCHAR` 内部存储结构、性能完全一致，`TEXT` 省去长度管理的心智负担与扩长度 DDL |
| 金额（`_cents`） | `bigint` | 严禁 `int`（溢出）、严禁 `float` / `double` / `numeric` / `decimal`（精度、换算/舍入策略不统一） |
| 多币种金额（`amount_minor`，例外场景） | `bigint` | 同上，无例外；仅在满足[表设计规范 2.2 多币种例外](../table-design.md#22-多币种例外commerce-multi-currency-exceptionmay)的条件时使用，需与 `currency_code` + `currency_exponent` 成组出现 |
| 货币代码（`currency_code`） | `text` | ISO 4217 三位字母码；严禁 `VARCHAR(N)` / `CHAR(N)` |
| 货币指数（`currency_exponent`） | `int` | 该币种 ISO 4217 小数位指数，配合 `amount_minor` 换算展示金额 |
| 时间点（`_at`） | `timestamptz` | 带时区，存储内容统一为 UTC |
| 乐观锁 `version` | `int` | `NOT NULL DEFAULT 0` |

## 2. 分区表主键例外（MAY）

PostgreSQL 声明式分区（`PARTITION BY RANGE` / `LIST` / `HASH`）要求**所有唯一约束（含主键）必须包含分区键**，因此按非 `id` 字段分区的表，无法保持[表设计规范](../table-design.md#1-主键策略)默认的单列自增主键形态，需退化为复合主键。

**适用范围**：仅当表因业务需要（数据量增长、生命周期管理、按分区批量清理等）**必须**按 `id` 以外的字段分区时触发；**严禁**为了凑单列主键而放弃必要的分区，也**严禁**反过来为图省事随意分区。

**落地方式**：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | `bigint GENERATED BY DEFAULT AS IDENTITY` | 保持不变，仍是唯一自增标识，不因分区丧失 IDENTITY 语义 |
| 主键 | `PRIMARY KEY (id, [分区键])` | 复合主键，分区键作第二列，满足 PG 对分区表的强制要求 |

示例（按 `created_at` 月度分区的会话表）：

```sql
CREATE TABLE "user_session" (
    "id"         bigint GENERATED BY DEFAULT AS IDENTITY,
    "jti"        TEXT NOT NULL,
    "created_at" TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY ("id", "created_at")
) PARTITION BY RANGE ("created_at");

CREATE UNIQUE INDEX "uniq__user_session__jti__created_at" ON "user_session"("jti", "created_at");
```

**强制要求**：

1. **表注释强制声明**：采用本例外的表，表注释必须以 `[分区主键例外]` 开头并说明分区依据，如：`[分区主键例外] 按 created_at 月度分区，主键为 (id, created_at)。`；
2. **业务唯一键必须补建包含分区键的唯一索引**：若表存在业务唯一键（如会话表的 `jti`），仍需按[索引规范](../indexing.md)建唯一索引，但**必须以分区键作为末位列**（如 `uniq__user_session__jti__created_at`）；
3. **明确该唯一索引的边界**：上述唯一索引**只保证"业务唯一键 + 分区键"组合唯一，不保证业务唯一键跨分区绝对唯一**——这是 PG 分区机制的固有限制，不是实现疏漏，**严禁**在文档或注释中描述为"数据库保证全局唯一"；
4. **跨分区唯一性由应用层兜底，不得新增全局映射表**：若业务要求该唯一键实际不可跨分区重复（如 `jti` 需近似全局唯一），须依靠生成算法自身的低碰撞概率（足够熵值的随机值）及业务生成不变量保证；**禁止**为此另建全局唯一映射表或做跨分区查重（违反[架构红线规范](architecture.md)的高并发原则），并须在字段注释中说明该风险已被评估和接受。

## 3. 排序规则（Collation）

**统一使用 `C`（或 `C.UTF-8`）**，建库时通过 `LC_COLLATE` / `LC_CTYPE` 固定，全项目一致。

- **严禁**业务表/字段混用不同 collation（排序与字符串比较行为不一致）；
- **警惕 glibc 升级导致 collation 版本变化使 `TEXT` 索引静默损坏**（PG 14+ 关注 `collversion` 告警，必要时 `REINDEX`）；
- 需要大小写不敏感查询时，使用 `citext` 扩展或在应用层处理，不改列级 collation。

## 4. Schema 使用

**默认使用 `public` schema**，不额外划分业务 schema。`search_path` 保持默认值。

## 5. `now()` 语义注意（MUST）

`now()` 返回**事务开始时间**，长事务中多条记录的 `created_at` 会完全相同。审计/日志场景如需精确到语句执行时刻，应用层应传入 `clock_timestamp()` 或改用该函数作为默认值。

## 6. 序列命名

使用 `GENERATED BY DEFAULT AS IDENTITY` 时，PostgreSQL 自动创建序列且命名固定为 `[表名]_[字段名]_seq`（如 `order_info_id_seq`），**建表语法上无法指定序列名**。

**统一落地方式（二选一，全项目只能选一种，默认推荐方案A）**：

- **方案A（推荐）**：接受默认命名 `[表名]_[字段名]_seq`，不额外干预。理由：IDENTITY 是声明式语法，序列是其实现细节，重命名属于过度设计；且 `pg_dump`、逻辑复制等生态工具对默认命名兼容性最好。
- **方案B**：建表后显式重命名：`ALTER SEQUENCE order_info_id_seq RENAME TO seq__order_info__id;`。仅在已有外部系统/脚本依赖 `seq__` 前缀命名时采用，且必须写进建表迁移脚本。

**严禁**：手工 `CREATE SEQUENCE` + 字段 `DEFAULT nextval(...)` 绕开 IDENTITY（失去 IDENTITY 的元数据管理与权限联动）。

## 7. 注释语法

PostgreSQL 使用独立的 `COMMENT ON` 语句（通用注释模板见[表设计规范](../table-design.md)）：

```sql
COMMENT ON TABLE order_info IS '订单主表，存储用户下单的核心订单数据。';
COMMENT ON COLUMN order_info.order_no IS '订单编号，用户侧展示的唯一业务编号。';
COMMENT ON COLUMN order_info.user_id IS '关联 user_info.id；下单用户ID。';
COMMENT ON COLUMN order_info.user_nickname IS '[冗余] 来源：user_info.nickname；下单时用户名快照，避免联表查询。';
COMMENT ON COLUMN order_info.order_status IS '订单状态。枚举：INIT=待支付, PAID=已支付, SHIPPED=已发货, COMPLETED=已完成, CANCELED=已取消。';
```

## 8. PG 专项禁用清单

在[通用禁用清单](../architecture.md)基础上，PostgreSQL 额外禁止：

- ❌ `GENERATED ALWAYS AS IDENTITY`（统一用 `GENERATED BY DEFAULT`）
- ❌ `BIGSERIAL`（统一用 IDENTITY）
- ❌ `VARCHAR(N)` / `CHAR(N)`（字符串统一用 `TEXT`）

完整可执行 DDL 示例见 [ddl-example.md](ddl-example.md)。
